# Развёртывание — v0.4

## Диагностика по вашему скриншоту

**1. «Chart is not defined» на табло.** Была зафиксирована версия Chart.js
(`4.4.4`), которой, похоже, нет на cdnjs — скрипт не загрузился, и ошибка
попала в то же сообщение, что и «не удалось связаться с сервером» (хотя
сервер отвечал нормально). Исправлено: версия `4.5.0` (подтверждена в
каталоге cdnjs), плюс ошибки загрузки библиотеки графиков и ошибки сети
теперь показывают разный текст.

**2. «Месяц 1 из undefined».** Значит в листе `Config` физически нет строки
`TOTAL_ROUNDS` — либо `setupSheets()` не перезапускали после обновления
`Code.gs`, либо она не добавилась. Починил на уровне кода навсегда:
`getCfg_()` теперь сам подставляет дефолт для ЛЮБОГО отсутствующего или
нечислового ключа конфига, а не тихо пропускает `undefined` в формулы —
это не требует повторного запуска `setupSheets()`, хотя его всё равно
стоит запустить, чтобы сами строки появились в Config для наглядности.

**3. Астрономические цифры кассы (−1,78 триллиона ฿) и ёмкость 9 500 на
«месяце 1».** Это я не могу подтвердить со стопроцентной уверенностью, не
видя вашу таблицу, но по косвенным признакам на скриншоте это **не новый
баг в расчёте**, а накопленное состояние от МНОГИХ предыдущих тестовых
раундов:
  - Ёмкость 9 500 = `CAPACITY_BASE (4500) + 5 смен × 1000`. За один месяц
    смена может измениться максимум на ±1 — значит, чтобы дойти до 9 500,
    нужно было сыграть минимум 5 реальных раундов, а не один.
  - Выручка и число обслуженных клиентов на скриншоте выглядят совершенно
    нормально (не NaN, пропорциональны разной ёмкости игроков) — значит,
    сама формула распределения спроса считает верно. Расхождение — где-то
    в исторически накопленной кассе/бренде, а не в текущем расчёте.
  - Похоже на то, что данные `Rounds` стирались вручную (до появления
    кнопки сброса) — счётчик месяца обнулился до «Месяц 1», а вот
    `Players`/`Results` остались от предыдущих тестов со всей историей
    убытков.

  **Решение**: используйте кнопку сброса — Пульт администратора →
  «Опасная зона» → «Начать игру заново» → наберите код игры (`GAME_CODE`
  из Config) → «Подтвердить сброс». Она чистит `Players`, `Decisions`,
  `Results`, `BankLog` и `Rounds` СРАЗУ ВМЕСТЕ, так что не может остаться
  рассинхронизации между «месяц сбросился» и «касса не сбросилась». После
  этого начните месяц 1 заново и проверьте, что цифры выглядят разумно.

  Если после чистого сброса аномалия повторится — проверьте в `Config`
  значения `RENT`, `PAYROLL_BASE`, `CAPACITY_STEP_COST` на предмет лишних
  нулей (частая причина именно такого масштаба ошибки — не баг в
  формуле, а опечатка в константе), и пришлите содержимое строки Results
  за проблемный месяц — по ней сразу видно, в какой именно статье П&У
  расхождение.

## Обновление уже развёрнутого проекта

1. Замените `Code.gs`, запустите `setupSheets()` ещё раз (не обязательно
   после этого обновления благодаря дефолтам конфига, но не помешает).
2. Замените все 6 файлов фронтенда в репозитории GitHub Pages.
3. **Обязательно**: Пульт администратора → «Опасная зона» → сброс игры,
   прежде чем начинать новый тест — чтобы не тащить старое накопленное
   состояние из предыдущих экспериментов.

## 1. Google Sheets + Apps Script (бэкенд)

1. Создайте таблицу → Расширения → Apps Script (или откройте существующий
   проект, если обновляете).
2. Скопируйте содержимое `Code.gs` в редактор.
3. Запустите `setupSheets()`. Безопасно запускать повторно.
4. В листе **Config**: `ADMIN_USERNAME` — ваш ник без `@`;
   `TOTAL_ROUNDS` — длина партии (1–36, по умолчанию 12);
   `ROUND_DURATION_MIN` — минут на приём решений (по умолчанию 5).
5. В листе **Players**: на игрока — только `telegram_username` (без `@`).
6. **Deploy → New deployment → Web app.** Execute as: **Me**.
   Who has access: **Anyone**. Скопируйте `.../exec`-ссылку.

## 2. GitHub Pages (фронтенд)

1. Публичный репозиторий, в корень: `index.html` (строго строчными!),
   `Style.css`, `App.js`, `tablo.html`, `tablo.css`, `tablo.js`.
2. `EXEC_URL` в начале `App.js` и `tablo.js` — ссылка из шага 1.6, в **оба**
   файла.
3. Settings → Pages → Source: `main` / `/ (root)`.
4. Кабинет: `https://<логин>.github.io/<репо>/` — в BotFather.
   Табло: `.../tablo.html` — на проектор/ТВ отдельной вкладкой.

## Как проходит месяц

1. Администратор жмёт «Открыть ввод решений» → сервер фиксирует дедлайн
   (сейчас + `ROUND_DURATION_MIN` минут).
2. На всех экранах — крупный таймер обратного отсчёта, краснеет в
   последние 30 секунд.
3. Игроки отправляют решения. Кто не успел — используется прошлое решение
   (или цена по умолчанию).
4. По истечении времени сервер сам считает месяц и закрывает приём —
   результаты добавляются к истории, видно в кабинетах и на табло.
5. Администратор может закрыть месяц раньше кнопкой «Рассчитать месяц».

## Проверка перед игрой

- `.../?u=<ник_админа>` — пульт ведущего: «Открыть ввод решений» /
  «Рассчитать месяц» / «Опасная зона» со сбросом.
- `.../?u=<ник_игрока>` — онбординг → кабинет.
- `.../tablo.html` — 4 графика + блок техданных в углу; до первого месяца
  — «Пока нет данных», при сбое — понятный текст, а не тишина.
- Откройте месяц → таймер тикает на всех трёх экранах одинаково →
  краснеет за 30 сек до конца → по истечении — месяц считается сам.
- Проверьте сброс: «Опасная зона» → «Начать игру заново» → код игры →
  подтвердить → все листы данных пустые (кроме шапки), Rounds — с месяца 0.

## Технические детали API

`Code.gs` принимает:

- **GET** `?action=identify|dashboard|monitor|config|public|timeline&u=ник`
- **POST** тело `{ "action": "...", "username": "...", "payload": {...} }`,
  `Content-Type: text/plain`. Действия: `submitDecision`, `requestLoan`,
  `repayLoan`, `markBankRead`, `setProfile`, `adminUpdateConfig`,
  `adminOpenRound`, `adminCalculateRound`, `adminResetGame`.

`?action=timeline` — публичный, без авторизации: полная история по
месяцам, объём рынка по месяцам, и блок `techInfo` с текущими техданными.

## Что сознательно упрощено в этой сборке (v0)

- Один сегмент рынка вместо трёх (эконом/масс/премиум).
- Переполнение ёмкости — клиенты просто теряются, без перетока к соседям.
- Банкротство — только флаг `status=bankrupt`, без сценариев продажи
  бизнеса/найма — решается вручную с ведущим по ходу игры.
- Формат заведения, реклама (кроме Google Карт) и вложения в качество
  действуют в том же месяце, без лага.
- `VERIFY_TELEGRAM_AUTH` выключен в `Config` — ник берётся из
  `initDataUnsafe` без криптопроверки HMAC.
- Автозакрытие месяца полагается на регулярный опрос хотя бы одного
  экрана — на практике это всегда так, но абсолютная секундная точность
  не гарантируется (без отдельного серверного триггера, который сознательно
  не добавлен — усложнил бы разрешения проекта ради сценария, который на
  практике не возникает).
- Численные коэффициенты 6 маркетинговых каналов — v0-интерпретация
  качественных описаний из брифа, требуют калибровки по живым прогонам.

Все цифры экономики — в листе **Config**, меняются без переразвёртывания
Apps Script (кроме структуры листов) и без прикосновения к GitHub Pages.
