## Побочно найденный и исправленный баг банка

Тестируя выбор суммы кредита, наткнулся на реальный дефект, который жил
в коде с самого добавления банковской системы: **`checkBankTiers_`

Уведомление «лимит увеличен» уходило верно, но сам `loan_tier` в таблице
так и оставался 0 навсегда — именно поэтому в мониторе администратора в
колонке «Банк» всегда был 0, даже после сообщений о повышении лимита.
Починено: порядок вызовов поменян местами, повышение уровня теперь
реально сохраняется.

## Доработка 2 — общий рынок

Проверил по вашим же данным: сумма обслуженных клиентов и раньше никогда
не превышала объём рынка (это гарантировано формулой распределения) — но
объём рынка масштабировался как `MARKET_SIZE_PER_PLAYER × число игроков`,
поэтому при двух игроках рынок был ~9000, а не 4500. Это было осознанное
решение с самого начала проекта (чтобы при 12 игроках рынок не мельчал
до нежизнеспособных долей), но раз сейчас нужно иначе — добавил
переключатель:

- **`Config → MARKET_SCALES_WITH_PLAYERS = TRUE`** (по умолчанию) — рынок
  растёт с числом игроков, как было.
- **`= FALSE`** — рынок ФИКСИРОВАН и равен `MARKET_SIZE_PER_PLAYER`
  целиком независимо от числа игроков — настоящий общий ограниченный
  ресурс, за который все конкурируют один-в-один. Проверено тестом: при
  двух игроках и `FALSE` рынок = ровно 4500, сумма обслуженных ≤ 4500.

Переключается без переразвёртывания — прямо в листе Config.

## Доработка 3 — таблица маркетинга на табло

Новая 5-я вкладка **«Маркетинг (таблица)»** рядом с графиками — не
график, таблица по месяцам (последний месяц сверху), для каждого игрока:
цена, бюджет на рекламу (сумма всех 6 каналов), выбранная стратегия
(доминирующий канал, если на него ушло ≥60% бюджета, иначе «Смешанная
(A+B)»), и отдельно посчитанный «рекламный эффект» — вклад именно
маркетинга в привлекательность заведения, без смешивания с брендом,
качеством и ценой. Строки игроков в одном месяце идут подряд — удобно
сравнивать по горизонтали.

## Обновление уже развёрнутого проекта

1. Замените `Code.gs` целиком.
2. **Deploy → Manage deployments → ✏️ → Version: New version → Deploy.**
   Не забудьте этот шаг — без него изменения не попадут в `/exec`.
3. Запустите `setupSheets()` — пересоздаст игровые листы (Config не
   тронет), добавит колонки `price`/`marketing_effect` в Results.
4. Замените все 6 файлов фронтенда в репозитории GitHub Pages.
5. «Опасная зона» → сброс игры, прежде чем начинать новый тест.

## Проверка перед игрой

- В кабинете игрока: «Доступно к получению» показывает разумное число,
  можно ввести сумму меньше максимума и получить именно её.
- После пары месяцев с положительным потоком — уровень банка в мониторе
  администратора должен реально расти (не оставаться 0).
- Табло → «Маркетинг (таблица)» — видно строки по каждому игроку за
  каждый месяц с ценой, бюджетом, стратегией, эффектом.
- При желании проверить фиксированный рынок — поставьте
  `MARKET_SCALES_WITH_PLAYERS=FALSE` в Config и сыграйте месяц с
  несколькими игроками: сумма «обслужено» не должна превышать
  `MARKET_SIZE_PER_PLAYER`.

## Технические детали API

`Code.gs` принимает:

- **GET** `?action=identify|dashboard|monitor|config|public|timeline&u=ник`
- **POST** тело `{ "action": "...", "username": "...", "payload": {...} }`,
  `Content-Type: text/plain`. Действия: `submitDecision`,
  `requestLoan` (теперь `{amount}`, без `tier`), `repayLoan`,
  `markBankRead`, `setProfile`, `adminUpdateConfig`, `adminOpenRound`,
  `adminCalculateRound`, `adminResetGame`.

## Что сознательно упрощено в этой сборке (v0)

- Один сегмент рынка вместо трёх (эконом/масс/премиум).
- Переполнение ёмкости — клиенты просто теряются, без перетока к соседям.
- Банкротство — только флаг `status=bankrupt`, без сценариев продажи
  бизнеса/найма — решается вручную с ведущим по ходу игры.
- Формат заведения, реклама (кроме Google Карт) и вложения в качество
  действуют в том же месяце, без лага.
- `VERIFY_TELEGRAM_AUTH` выключен в `Config` — ник берётся из
  `initDataUnsafe` без криптопроверки HMAC.
- Численные коэффициенты 6 маркетинговых каналов — v0-интерпретация
  качественных описаний из брифа, требуют калибровки по живым прогонам.

Все цифры экономики — в листе **Config**, меняются без переразвёртывания
Apps Script (кроме структуры листов) и без прикосновения к GitHub Pages.
