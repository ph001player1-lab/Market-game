# Развёртывание — v0.8

## Что нового в этой версии

### Банкротство и найм — реализовано полностью

Раньше отрицательная касса просто ставила флаг `bankrupt`, и игрок навсегда
выпадал из игры без вариантов. Теперь это полноценный жизненный цикл:

1. Касса ушла в минус → статус `bankrupt`. В кабинете вместо обычного
   экрана — выбор: **«Пойти в найм»** или **«Закончить участие в игре»**.
2. **Найм** (`employed`): фиксированная зарплата (`EMPLOYMENT_SALARY`,
   по умолчанию 35 000 ฿) начисляется автоматически каждый закрытый
   месяц — решений принимать не нужно, игрок просто наблюдает, как растут
   накопления.
3. Как только накоплено ≥ `REOPEN_THRESHOLD` (по умолчанию 100 000 ฿,
   равно новому стартовому капиталу) — в кабинете появляется кнопка
   **«Открыть новое дело»**. Переоткрытие даёт полностью свежий старт:
   бренд, репутация, качество, все 6 маркетинговых каналов и банковский
   уровень обнуляются, стартовый капитал — это и есть накопленное за
   время найма.
4. **«Закончить участие»** (`left`) — терминальное состояние, кабинет
   показывает прощальный экран, дальше игрок просто зритель (табло).

Банкроты, наёмные и вышедшие полностью исключены из расчёта месяца —
не участвуют в распределении рынка, не занимают чужую долю.

### Стартовый капитал — 100 000 ฿ вместо 2 000 000 ฿

Меняет саму суть игры: буфер прочности теперь маленький, ошибка в
ценообразовании или рекламе может обанкротить в первый же месяц.
Это осознанно — раз банкротство должно быть реальным финалом, а не
теоретической строкой в отчёте.

### Перевод денег между игроками

Новая карточка «Перевести деньги другому игроку» в кабинете: выбор
получателя из списка активных/наёмных игроков, сумма — в пределах
текущей кассы отправителя (автоматически урезается, если ввели больше).
Получателю в найме деньги идут в накопления на открытие дела, активному
игроку — прямо в кассу. Каждый перевод пишется в новый лист **Transfers**
(от кого, кому, сколько, когда) — полный аудит сговоров и взаимопомощи.

### Индикация загрузки

Любая кнопка, которая обращается к серверу (решение месяца, кредит,
погашение, перевод, все кнопки администратора, сброс игры), сразу после
нажатия блокируется и меняет текст на «Обработка…» / «Считаем…» и т.п.,
пока идёт запрос — больше не возникает ощущения, что нажатие не
засчиталось.

### Монитор администратора — колонка «Статус»

Показывает читаемым текстом: активен / банкрот (выбирает) / в найме /
вышел из игры — иначе банкроты и наёмные вечно висели бы с «…» в
колонке «Ход» без объяснений.

## Обновление уже развёрнутого проекта

1. Замените `Code.gs`, запустите `setupSheets()` — добавит колонку
   `employment_savings` в Players и новый лист `Transfers`, новые ключи
   `EMPLOYMENT_SALARY`/`REOPEN_THRESHOLD` в Config. **`START_CAPITAL`
   уже существует в вашем Config с прошлым значением — новый дефолт
   (100 000) применится только к НОВЫМ ключам; если хотите изменить
   существующее значение, поправьте его в Config вручную.**
2. **Deploy → Manage deployments → ✏️ → Version: New version → Deploy.**
3. Замените все 6 файлов фронтенда в репозитории GitHub Pages.
4. «Опасная зона» → сброс игры — раз меняется стартовый капитал и вся
   механика банкротства, текущую партию лучше не продолжать.

## Архитектура (без изменений)

- **`Code.gs`** — бэкенд на Apps Script, JSON API.
- **`index.html` + `Style.css` + `App.js`** — кабинет игрока/администратора.
- **`tablo.html` + `tablo.css` + `tablo.js`** — табло для проектора/ТВ.
- **`EXEC_URL` меняется в ДВУХ местах**: `App.js` и `tablo.js`.

## 1. Google Sheets + Apps Script (бэкенд)

1. Создайте таблицу → Расширения → Apps Script (или откройте существующий
   проект).
2. Скопируйте содержимое `Code.gs` в редактор, полностью заменив старое.
3. Запустите `setupSheets()`.
4. В листе **Config**: `ADMIN_USERNAME` — ваш ник без `@`; `TOTAL_ROUNDS`
   (1–36); `ROUND_DURATION_MIN`; при желании — `START_CAPITAL`,
   `EMPLOYMENT_SALARY`, `REOPEN_THRESHOLD`.
5. В листе **Players**: на игрока — только `telegram_username` (без `@`).
6. **Deploy → New deployment → Web app.** Execute as: **Me**.
   Who has access: **Anyone**. Скопируйте `.../exec`-ссылку — или, если
   деплой уже есть, используйте «Manage deployments → New version», чтобы
   ссылка не менялась.

## 2. GitHub Pages (фронтенд)

1. Публичный репозиторий, в корень: `index.html` (строго строчными!),
   `Style.css`, `App.js`, `tablo.html`, `tablo.css`, `tablo.js`.
2. `EXEC_URL` в начале `App.js` и `tablo.js` — ссылка из шага 1.6, в **оба**
   файла.
3. Settings → Pages → Source: `main` / `/ (root)`.
4. Кабинет: `https://<логин>.github.io/<репо>/` — в BotFather.
   Табло: `.../tablo.html` — на проектор/ТВ отдельной вкладкой.

## Проверка перед игрой

- Доведите игрока до отрицательной кассы (агрессивный демпинг + большая
  реклама на маленьком стартовом капитале — теперь легко) → должен
  появиться экран выбора «найм / закончить».
- Выберите «найм» → в мониторе администратора статус должен показывать
  «в найме», а сам игрок — накопления, растущие на 35 000 ₿ за каждый
  закрытый месяц, без каких-либо решений с его стороны.
- Когда накопится 100 000 ₿ — должна появиться кнопка «Открыть новое
  дело»; после нажатия бренд/репутация/качество должны быть обнулены.
- Проверьте перевод денег между двумя платёжеспособными игроками — сумма
  должна списаться у отправителя и прийти получателю, запись — в листе
  `Transfers`.
- Нажмите любую кнопку с сетевым действием — она должна сразу
  заблокироваться и показать текст вида «Обработка…» до ответа сервера.
- Если на табло всё ещё видно старую версию (5 кнопок вместо 6, или
  плавающий блок техданных поверх графика) — это кэш браузера или
  GitHub Pages, а не код: сделайте жёсткий рефреш (Ctrl+Shift+R) и
  проверьте прямо в репозитории на GitHub, что `tablo.html` содержит
  актуальное содержимое.

## Технические детали API

`Code.gs` принимает:

- **GET** `?action=identify|dashboard|monitor|config|public|timeline&u=ник`
- **POST** тело `{ "action": "...", "username": "...", "payload": {...} }`,
  `Content-Type: text/plain`. Действия: `submitDecision`, `requestLoan`,
  `repayLoan`, `transferMoney`, `chooseBankruptcyPath`, `reopenBusiness`,
  `markBankRead`, `setProfile`, `adminUpdateConfig`, `adminOpenRound`,
  `adminCalculateRound`, `adminResetGame`.

`getDashboard` теперь возвращает поле `lifecycle`: `active` (обычный
кабинет), `bankrupt` (экран выбора), `employed` (экран найма), `left`
(прощальный экран) — фронтенд ветвится по этому полю.

## Что сознательно упрощено в этой сборке (v0)

- Один сегмент рынка вместо трёх (эконом/масс/премиум).
- Переполнение ёмкости — клиенты просто теряются, без перетока к соседям.
- Формат заведения, реклама (кроме Google Карт) и вложения в качество
  действуют в том же месяце, без лага.
- `VERIFY_TELEGRAM_AUTH` выключен в `Config` — ник берётся из
  `initDataUnsafe` без криптопроверки HMAC.
- Численные коэффициенты 6 маркетинговых каналов, зарплата в найме и
  порог переоткрытия — v0-интерпретация, требуют калибровки по живым
  прогонам, особенно с учётом нового, гораздо более скромного стартового
  капитала.

Все цифры экономики — в листе **Config**, меняются без переразвёртывания
Apps Script (кроме структуры листов) и без прикосновения к GitHub Pages.
