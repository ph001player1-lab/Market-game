# Развёртывание — v0.14

## EXEC_URL — проверено, лишних мест нет

Специально прогрепал весь проект: `EXEC_URL` определяется ровно в двух
местах — `App.js` (строка 4) и `tablo.js` (строка 2). Больше нигде
(`Code.gs`, `index.html`, `Style.css`, `tablo.html`, `tablo.css`) этой
переменной нет вообще, только упоминания в комментариях `Code.gs`,
отсылающие к этим двум файлам. Если ссылка вписана в оба и всё равно не
работает — дело не в третьем скрытом месте.

## Про «кабинет открывается, но нет формы решения»

Судя по присланному ранее xlsx, у двух из трёх игроков в листе Players
все поля (включая `display_name`/`restaurant_name`) были пустыми — это
значит, что они ещё не прошли экран онбординга («Добро пожаловать!» —
имя + название заведения). Пока это так, кабинет специально показывает
только онбординг, а не форму решения — это ожидаемое поведение, а не
баг: полный кабинет открывается только после того, как онбординг
заполнен. Если игрок утверждает, что заполнял его, но всё равно не
видит форму — пришлите новый xlsx-экспорт, посмотрим, сохранились ли
после этого `display_name`/`restaurant_name`.

Отдельно: `Rounds` в том же файле содержал только «нулевой» месяц
(`closed`) — ни один месяц ещё ни разу не был открыт администратором.
Это отдельно объясняет «данные не сохраняются» для остальных игроков:
`submitDecision` корректно отклоняет решение, если месяц не в статусе
`open` — отправлять было не во что. После нажатия «Открыть ввод решений»
это должно решиться само.

## Обновление уже развёрнутого проекта

1. Замените все 7 файлов (только версии в шапках — функциональных
   изменений в этот раз нет).
2. **Deploy → Manage deployments → ✏️ → Version: New version → Deploy.**
3. Проверьте `EXEC_URL` в `App.js` и `tablo.js` — обе ссылки должны
   быть одинаковыми и настоящими, без плейсхолдера.
4. Нажмите «Открыть ввод решений» в пульте администратора, если ещё
   не нажимали после последнего исправления ссылки.
5. У игроков с пустым кабинетом — проверьте, прошли ли они экран
   «Добро пожаловать!» (онбординг).

## Архитектура (без изменений)

- **`Code.gs`** — бэкенд на Apps Script, JSON API, всё через GET.
- **`index.html` + `Style.css` + `App.js`** — кабинет игрока/администратора.
- **`tablo.html` + `tablo.css` + `tablo.js`** — табло для проектора/ТВ.
- **`EXEC_URL` меняется в ДВУХ местах**: `App.js` и `tablo.js`.

## 1. Google Sheets + Apps Script (бэкенд)

1. Создайте таблицу → Расширения → Apps Script (или откройте существующий
   проект).
2. Скопируйте содержимое `Code.gs` в редактор, полностью заменив старое.
3. Запустите `setupSheets()` (▶ в редакторе — результат смотрите в
   логах, не во всплывающем окне).
4. В листе **Config**: `ADMIN_USERNAME` — ваш ник без `@`.
5. В листе **Players**: на игрока — только `telegram_username` (без `@`).
6. **Deploy → New deployment → Web app.** Execute as: **Me**.
   Who has access: **Anyone**.

## 2. GitHub Pages (фронтенд)

1. Публичный репозиторий, в корень: `index.html` (строго строчными!),
   `Style.css`, `App.js`, `tablo.html`, `tablo.css`, `tablo.js`.
2. `EXEC_URL` в начале **и `App.js`, и `tablo.js`**.
3. Settings → Pages → Source: `main` / `/ (root)`.
4. Кабинет: `https://<логин>.github.io/<репо>/` — в BotFather.
   Табло: `.../tablo.html` — на проектор/ТВ отдельной вкладкой.

## Проверка перед игрой

- Откройте `.../exec` напрямую — `{"ok":true,"status":"API работает..."}`.
- Пульт администратора → «Открыть ввод решений» → у игроков, прошедших
  онбординг, должна появиться форма решения.
- У новых игроков без имени/заведения — экран «Добро пожаловать!»,
  заполните — должен открыться полный кабинет.

## Что сознательно упрощено в этой сборке (v0)

- Один сегмент рынка вместо трёх (эконом/масс/премиум).
- Переполнение ёмкости — клиенты просто теряются, без перетока к соседям.
- Формат заведения, реклама (кроме Google Карт) и вложения в качество
  действуют в том же месяце, без лага.
- `VERIFY_TELEGRAM_AUTH` выключен в `Config` — ник берётся из
  `initDataUnsafe` без криптопроверки HMAC.
- Численные коэффициенты 6 маркетинговых каналов, зарплата в найме и
  порог переоткрытия — v0-интерпретация, требуют калибровки по живым
  прогонам.

Все цифры экономики — в листе **Config**, меняются без переразвёртывания
Apps Script (кроме структуры листов) и без прикосновения к GitHub Pages.
