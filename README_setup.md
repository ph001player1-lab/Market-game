# Развёртывание — v0.5

## Критический баг найден и исправлен (спасибо за присланный xlsx!)

**Причина обеих проблем со скриншота — одна.** `submitDecision()` писал
решение игрока в лист `Decisions` **по позиции** (просто массив значений
по порядку), а не по названиям колонок. Это работает, только если реальный
порядок колонок в листе совпадает с тем, что предполагает код. У вас же
лист создавался ещё в старой версии (когда был единственный `ad_spend`),
а 6 новых каналов дописались в конец при миграции — то есть реальный
порядок колонок отличался от того, что писал код. В результате:

- в `shifts_delta` попадало значение поля «Промоутеры» → зажималось до
  максимума +5 смен → отсюда ёмкость **9 500**;
- в `quality_invest` попадало значение поля «Google Карты» → отсюда
  «Качество 0.03», которого никто не заказывал;
- в `outdoor_spend` попадал сам `Date`-объект времени отправки — а
  `Number(дата)` в JS это миллисекунды с 1970 года, то есть число вида
  `1 784 997 008 041`. Оно одновременно (а) включало наружную рекламу
  почти с одинаковой гигантской силой у ОБОИХ игроков (отсюда «поровну»,
  несмотря на разную реальную рекламу — общая огромная погрешность
  забивала собой реальные различия) и (б) попадало прямиком в сумму
  `marketing_total`, а оттуда — в убыток триллионного масштаба.

**Исправлено**: запись решения теперь строго по именам колонок — как уже
было в `writeResults_`/`writePlayersBack_`, которые поэтому не пострадали.
Заодно тем же способом исправлены `adminOpenRound` (открытие месяца) и
`checkBankTiers_` (запись в BankLog) — там был тот же риск, хоть в вашем
случае и не выстрелил. Проверено тестом: тот же легаси-порядок колонок,
что и в вашей таблице → все 6 каналов, смены и качество теперь ложатся
именно туда, куда должны, `marketing_total` получается разумным (сумма
реальных трат), касса после месяца — с реалистичным знаком и порядком.

**Что делать**: замените `Code.gs`, затем — обязательно — «Опасная зона» →
«Начать игру заново» (месяц 1 в вашей игре сейчас безнадёжно испорчен этим
багом, оба игрока помечены `bankrupt` из-за фиктивного убытка; чинить его
на месте смысла нет, легче пересчитать с чистого месяца 1).

## 1. Google Sheets + Apps Script (бэкенд)

1. Создайте таблицу → Расширения → Apps Script (или откройте существующий
   проект, если обновляете).
2. Скопируйте содержимое `Code.gs` в редактор.
3. Запустите `setupSheets()`. Безопасно запускать повторно.
4. В листе **Config**: `ADMIN_USERNAME` — ваш ник без `@`;
   `TOTAL_ROUNDS` — длина партии (1–36, по умолчанию 12);
   `ROUND_DURATION_MIN` — минут на приём решений (по умолчанию 5).
5. В листе **Players**: на игрока — только `telegram_username` (без `@`).
6. **Deploy → New deployment → Web app.** Execute as: **Me**.
   Who has access: **Anyone**. Скопируйте `.../exec`-ссылку.

## 2. GitHub Pages (фронтенд)

1. Публичный репозиторий, в корень: `index.html` (строго строчными!),
   `Style.css`, `App.js`, `tablo.html`, `tablo.css`, `tablo.js`.
2. `EXEC_URL` в начале `App.js` и `tablo.js` — ссылка из шага 1.6, в **оба**

3. Settings → Pages → Source: `main` / `/ (root)`.
4. Кабинет: `https://<логин>.github.io/<репо>/` — в BotFather.

## Проверка перед игрой

- Сбросьте игру («Опасная зона»), откройте месяц 1, отправьте решения с
  РАЗНЫМИ числами в разных полях (например, у одного игрока SEO=1000,
  промоутеры=2000, карты=3000 и т.д. — все разные) → рассчитайте месяц →
  откройте лист `Decisions` в Google Sheets и убедитесь, что в каждой
  колонке лежит именно то число, которое вводилось для этого канала.
- Проверьте, что `marketing_total` в `Results` равен сумме шести реальных
  трат, а не аномально большому числу.
- Дальше — как раньше: таймер тикает на всех экранах, краснеет за 30 сек,
  месяц считается сам по истечении времени.

## Технические детали API

`Code.gs` принимает:

- **GET** `?action=identify|dashboard|monitor|config|public|timeline&u=ник`
- **POST** тело `{ "action": "...", "username": "...", "payload": {...} }`,
  `Content-Type: text/plain`. Действия: `submitDecision`, `requestLoan`,
  `repayLoan`, `markBankRead`, `setProfile`, `adminUpdateConfig`,
  `adminOpenRound`, `adminCalculateRound`, `adminResetGame`.

`?action=timeline` — публичный, без авторизации: полная история по
месяцам, объём рынка по месяцам, и блок `techInfo` с текущими техданными.

## Что сознательно упрощено в этой сборке (v0)

- Один сегмент рынка вместо трёх (эконом/масс/премиум).
- Переполнение ёмкости — клиенты просто теряются, без перетока к соседям.
- Банкротство — только флаг `status=bankrupt`, без сценариев продажи
  бизнеса/найма — решается вручную с ведущим по ходу игры.
- Формат заведения, реклама (кроме Google Карт) и вложения в качество
  действуют в том же месяце, без лага.
- `VERIFY_TELEGRAM_AUTH` выключен в `Config` — ник берётся из
  `initDataUnsafe` без криптопроверки HMAC.
- Автозакрытие месяца полагается на регулярный опрос хотя бы одного
  экрана — на практике это всегда так, но абсолютная секундная точность
  не гарантируется без отдельного серверного триггера (сознательно не
  добавлен — усложнил бы разрешения проекта).
- Численные коэффициенты 6 маркетинговых каналов — v0-интерпретация
  качественных описаний из брифа, требуют калибровки по живым прогонам.

Все цифры экономики — в листе **Config**, меняются без переразвёртывания
Apps Script (кроме структуры листов) и без прикосновения к GitHub Pages.
