# Развёртывание — v0.3

## Что нового в этой версии

- **Починка табло**: раньше при ошибке на сервере (например, после ручного
  удаления данных из `Rounds`) табло молча показывало пустой холст под
  кнопками. Теперь ошибка видна текстом, а `getCurrentRound_()` в `Code.gs`
  сам восстанавливает `Rounds`, если он оказался пуст.
- **Таймер месяца**: при открытии месяца сервер сохраняет точный дедлайн
  (сейчас + `ROUND_DURATION_MIN` минут из Config, по умолчанию 5). Обратный
  отсчёт крупно виден на всех трёх экранах — кабинет игрока, пульт
  администратора, табло — и краснеет в последние 30 секунд. По истечении
  времени сервер **сам** закрывает месяц и считает результаты — при
  следующем же обращении с любого экрана, без участия администратора.
  Опрос происходит достаточно часто (каждые ~8 сек с каждого устройства +
  сразу по истечении таймера на клиенте), поэтому расчёт срабатывает в
  течение нескольких секунд после дедлайна. Одновременные обращения с
  нескольких телефонов не приводят к двойному расчёту — это защищено
  блокировкой (`LockService`) и проверено на тесте (см. ниже).
- **До 36 месяцев вместо жёстких 12**: новая настройка `TOTAL_ROUNDS` в
  Config (по умолчанию 12, меняется на любое число до 36). Открыть месяц
  сверх этого лимита нельзя — везде видно «Месяц X из Y».
- **Кнопка сброса игры** в панели администратора («Опасная зона»):
  полностью очищает игроков, решения, историю месяцев и банковский журнал,
  чтобы начать с месяца 1. Настройки экономики (Config) не трогает.
  Подтверждение — не один клик: нужно набрать код текущей игры
  (`Config → GAME_CODE`) во второе поле.

## Архитектура (без изменений)

- **`Code.gs`** — бэкенд на Apps Script, JSON API.
- **`index.html` + `Style.css` + `App.js`** — кабинет игрока/администратора.
- **`tablo.html` + `tablo.css` + `tablo.js`** — табло для проектора/ТВ.
- **`EXEC_URL` меняется в ДВУХ местах**: `App.js` и `tablo.js`.

## Обновление уже развёрнутого проекта

1. Замените `Code.gs`, запустите `setupSheets()` ещё раз — добавит
   `TOTAL_ROUNDS`, `ROUND_DURATION_MIN` в Config и колонку `deadline` в
   Rounds, ничего не удаляя из уже введённого.
2. Замените `index.html`, `Style.css`, `App.js`, `tablo.html`, `tablo.css`,
   `tablo.js` в репозитории GitHub Pages.
3. `EXEC_URL` в `App.js` и `tablo.js` можно не трогать, если ссылка та же.
4. **Если попадали в ситуацию «стёр данные и не могу начать заново»** —
   теперь просто откройте пульт администратора → «Опасная зона» →
   «Начать игру заново» → наберите код игры → «Подтвердить сброс».
   Не нужно ничего чистить в Sheets руками.

## 1. Google Sheets + Apps Script (бэкенд)

1. Создайте таблицу → Расширения → Apps Script (или откройте существующий
   проект, если обновляете).
2. Скопируйте содержимое `Code.gs` в редактор.
3. Запустите `setupSheets()`. Безопасно запускать повторно.
4. В листе **Config**: `ADMIN_USERNAME` — ваш ник без `@`;
   `TOTAL_ROUNDS` — длина партии (1–36, по умолчанию 12);
   `ROUND_DURATION_MIN` — минут на приём решений (по умолчанию 5).
5. В листе **Players**: на игрока — только `telegram_username` (без `@`).
6. **Deploy → New deployment → Web app.** Execute as: **Me**.
   Who has access: **Anyone**. Скопируйте `.../exec`-ссылку.

## 2. GitHub Pages (фронтенд)

1. Публичный репозиторий, в корень: `index.html` (строго строчными!),
   `Style.css`, `App.js`, `tablo.html`, `tablo.css`, `tablo.js`.
2. `EXEC_URL` в начале `App.js` и `tablo.js` — ссылка из шага 1.6, в **оба**
   файла.
3. Settings → Pages → Source: `main` / `/ (root)`.
4. Кабинет: `https://<логин>.github.io/<репо>/` — в BotFather.
   Табло: `.../tablo.html` — на проектор/ТВ отдельной вкладкой.

## Как проходит месяц теперь

1. Администратор жмёт «Открыть ввод решений» → сервер фиксирует дедлайн
   (сейчас + `ROUND_DURATION_MIN` минут).
2. На всех экранах появляется крупный таймер обратного отсчёта.
3. Игроки обсуждают и отправляют решения. Кто не успел — его прошлое
   решение (или цена по умолчанию) используется автоматически.
4. По истечении времени — таймер краснеет последние 30 секунд, затем
   сервер сам считает месяц и закрывает приём. Результаты добавляются
   к истории (не заменяют её) — видно и в кабинетах, и на табло.
5. Администратор может закрыть месяц и раньше кнопкой «Рассчитать месяц».

## Проверка перед игрой

- `.../?u=<ник_админа>` — пульт ведущего, есть кнопки «Открыть ввод
  решений» / «Рассчитать месяц» и «Опасная зона» со сбросом.
- `.../?u=<ник_игрока>` — онбординг → кабинет.
- `.../tablo.html` — табло; до первого месяца покажет «Пока нет данных»,
  при ошибке на сервере — текст ошибки, а не пустой экран.
- Откройте месяц → на всех трёх экранах должен появиться и тикать
  одинаковый таймер → дождитесь 30 секунд до конца → таймер должен
  покраснеть → дождитесь нуля → месяц должен посчитаться сам, без нажатия
  «Рассчитать месяц».
- Проверьте сброс: «Опасная зона» → «Начать игру заново» → наберите
  код игры → после подтверждения `Players`/`Decisions`/`Results`/`BankLog`
  должны быть пустыми (кроме шапки), а `Rounds` — заново с месяца 0.

## Технические детали API

`Code.gs` принимает:

- **GET** `?action=identify|dashboard|monitor|config|public|timeline&u=ник`
- **POST** тело `{ "action": "...", "username": "...", "payload": {...} }`,
  `Content-Type: text/plain`. Действия: `submitDecision`, `requestLoan`,
  `repayLoan`, `markBankRead`, `setProfile`, `adminUpdateConfig`,
  `adminOpenRound`, `adminCalculateRound`, `adminResetGame`.

`adminOpenRound` может вернуть `game_finished` (достигнут `TOTAL_ROUNDS`) —
в этом случае нужен сброс через `adminResetGame`.

## Что сознательно упрощено в этой сборке (v0)

- Один сегмент рынка вместо трёх (эконом/масс/премиум).
- Переполнение ёмкости — клиенты просто теряются, без перетока к соседям.
- Банкротство — только флаг `status=bankrupt`, без сценариев продажи
  бизнеса/найма — решается вручную с ведущим по ходу игры.
- Формат заведения, реклама (кроме Google Карт) и вложения в качество
  действуют в том же месяце, без лага.
- `VERIFY_TELEGRAM_AUTH` выключен в `Config` — ник берётся из
  `initDataUnsafe` без криптопроверки HMAC.
- Автозакрытие месяца полагается на то, что хотя бы один экран (игрок,
  админ или табло) регулярно опрашивает сервер — в реальной игре это
  всегда так (все смотрят в свои телефоны/на проектор), но если вообще
  никто не откроет приложение в течение нескольких минут после дедлайна,
  расчёт произойдёт с задержкой при следующем обращении, а не строго
  секунда в секунду. Отдельный серверный триггер (`ScriptApp` time-based
  trigger) для абсолютной точности сознательно не добавлен — усложнил бы
  разрешения проекта ради сценария, который на практике не возникает.
- Численные коэффициенты 6 маркетинговых каналов — v0-интерпретация
  качественных описаний из брифа, требуют калибровки по живым прогонам.

Все цифры экономики — в листе **Config**, меняются без переразвёртывания
Apps Script (кроме структуры листов) и без прикосновения к GitHub Pages.
