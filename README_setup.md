# Развёртывание — v0.12

## Исправлен `SpreadsheetApp.getUi()`

`setupSheets()` вызывал `getUi().alert(...)` в конце — а это работает
только при вызове из настоящего интерфейса Google Таблиц (например,
клик по кастомному меню), а не при запуске через ▶ «Выполнить» в
редакторе кода, что и есть штатный способ запуска этой функции. Заменил
на `Logger.log(...)` — результат смотрите во вкладке «Executions» /
панели логов после запуска, ошибки больше не будет.

## Новые дефолты + важная защита

- `CAPACITY_BASE`: 4500 → **1000** (базовая ёмкость нового бизнеса).
- `START_CAPITAL`: подтверждаю — в коде уже стоит **100 000** (я менял
  это раньше). **Если у вас в реальном листе Config всё ещё 2 000 000 —
  это ожидаемо**: `setupSheets()` не переписывает уже существующие
  значения, только дописывает отсутствующие ключи. Откройте лист
  **Config** и вручную поправьте `START_CAPITAL` → `100000` и
  `CAPACITY_BASE` → `1000` — иначе новые дефолты в коде так и останутся
  неприменёнными к вашей игре.

**Важно нашёл сам, тестируя**: при базе ёмкости 1000 и минимуме −3 смены
(`CAPACITY_SHIFTS_MIN`) итоговая ёмкость уходила бы в **минус** (1000 −
3000 = −2000) — раньше это везение маскировалось тем, что база была
4500. Добавил абсолютный пол `CAPACITY_MIN` (по умолчанию 100) — ёмкость
никогда не опустится ниже него, в какой бы комбинации смен вы её ни
раскачивали. Проверено тестом.

## Валидация ввода — отклоняет, а не тихо обрезает

Раньше цена ниже минимума тихо поднималась до минимума, а перевод денег
сверх кассы тихо урезался до остатка — игрок не видел, что его ввод
изменили. Теперь оба случая **отклоняются с понятным предупреждением**,
и решение нужно переделать:

- Цена ниже `P_FLOOR` или выше расчётного потолка — отклоняется.
- Сумма всех трат в решении месяца (6 каналов рекламы + вложения в
  качество) больше текущей кассы — отклоняется целиком, с суммой и
  доступным остатком в сообщении.
- Перевод другому игроку больше, чем есть в кассе — отклоняется.

Проверка идёт в двух местах: сразу на клиенте (мгновенное предупреждение
без обращения к серверу) и повторно на сервере (на случай, если данные
на экране устарели) — так что защититься от некорректного ввода нельзя,
даже вызывая API напрямую.

## Табло — пояснения «вес» и «альфа»

Перед карточками каналов в разделе «Маркетинговые каналы» теперь есть
общий абзац: **вес** — насколько сильно канал может повлиять на
привлекательность заведения по сравнению с брендом, качеством и
остальными каналами; **альфа** — масштаб эффекта внутри самого канала
при бюджете, равном опорному.

## Обновление уже развёрнутого проекта

1. Замените `Code.gs`. **Deploy → Manage deployments → ✏️ → Version:
   New version → Deploy.**
2. Запустите `setupSheets()` — добавит `CAPACITY_MIN` в Config.
3. **Вручную** поправьте в листе Config: `START_CAPITAL` → `100000`,
   `CAPACITY_BASE` → `1000` (см. выше, почему это нужно сделать руками).
4. Замените `App.js` и все 3 файла табло (`tablo.html`, `tablo.css`,
   `tablo.js`).
5. «Опасная зона» → сброс игры перед новым тестом.

## Архитектура (без изменений)

- **`Code.gs`** — бэкенд на Apps Script, JSON API, всё через GET.
- **`index.html` + `Style.css` + `App.js`** — кабинет игрока/администратора.
- **`tablo.html` + `tablo.css` + `tablo.js`** — табло для проектора/ТВ.
- **`EXEC_URL` меняется в ДВУХ местах**: `App.js` и `tablo.js`.

## 1. Google Sheets + Apps Script (бэкенд)

1. Создайте таблицу → Расширения → Apps Script (или откройте существующий
   проект).
2. Скопируйте содержимое `Code.gs` в редактор, полностью заменив старое.
3. Запустите `setupSheets()` (▶ в редакторе — результат смотрите в
   логах, не во всплывающем окне).
4. В листе **Config**: `ADMIN_USERNAME` — ваш ник без `@`; проверьте
   `START_CAPITAL` (100000) и `CAPACITY_BASE` (1000) — если запускаете
   не с нуля, поправьте вручную.
5. В листе **Players**: на игрока — только `telegram_username` (без `@`).
6. **Deploy → New deployment → Web app.** Execute as: **Me**.
   Who has access: **Anyone**.

## 2. GitHub Pages (фронтенд)

1. Публичный репозиторий, в корень: `index.html` (строго строчными!),
   `Style.css`, `App.js`, `tablo.html`, `tablo.css`, `tablo.js`.
2. `EXEC_URL` в начале **и `App.js`, и `tablo.js`**.
3. Settings → Pages → Source: `main` / `/ (root)`.
4. Кабинет: `https://<логин>.github.io/<репо>/` — в BotFather.
   Табло: `.../tablo.html` — на проектор/ТВ отдельной вкладкой.

## Проверка перед игрой

- `setupSheets()` из редактора не должна падать с ошибкой про `getUi()`.
- Новый игрок стартует с кассой 100 000 ฿ и ёмкостью 1000 (если поправили
  Config вручную).
- Попробуйте сократить формат до предела (несколько месяцев подряд «−1
  смена») — ёмкость должна остановиться на `CAPACITY_MIN`, не уйти в минус.
- Отправьте решение с ценой ниже минимума или с тратами больше кассы —
  должно появиться предупреждение и решение не должно отправиться.
- Попробуйте перевести больше, чем есть в кассе — то же самое.
- Табло → «Техданные» → внизу — абзац про «вес» и «альфа» перед
  карточками каналов.

## Технические детали API

`Code.gs` принимает **всё через GET**. Новые коды ошибок:
`submitDecision` → `price_too_low`, `price_too_high`, `insufficient_cash`;
`transferMoney` → `insufficient_cash` (вместо тихого урезания суммы).

## Что сознательно упрощено в этой сборке (v0)

- Один сегмент рынка вместо трёх (эконом/масс/премиум).
- Переполнение ёмкости — клиенты просто теряются, без перетока к соседям.
- Формат заведения, реклама (кроме Google Карт) и вложения в качество
  действуют в том же месяце, без лага.
- `VERIFY_TELEGRAM_AUTH` выключен в `Config` — ник берётся из
  `initDataUnsafe` без криптопроверки HMAC.
- При базе ёмкости 1000 и прежних `RENT`/`PAYROLL_BASE`/
  `CAPACITY_STEP_COST` (150000/220000/60000) экономика может ощущаться
  разбалансированной — это не менял, вы не просили; отдельные постоянные
  расходы теперь велики относительно нового масштаба ёмкости и капитала.
  Стоит проверить на живом прогоне и при необходимости подправить в Config.
- Численные коэффициенты 6 маркетинговых каналов, зарплата в найме и
  порог переоткрытия — v0-интерпретация, требуют калибровки по живым
  прогонам.

Все цифры экономики — в листе **Config**, меняются без переразвёртывания
Apps Script (кроме структуры листов) и без прикосновения к GitHub Pages.
