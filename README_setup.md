# Развёртывание — v0.6

## ⚠️ Главное: похоже, у вас всё ещё выполняется СТАРЫЙ код

Судя по присланному xlsx, баг с триллионом воспроизводится **1 в 1** так же,
как раньше (`submitted_at` снова лежит числом в позиции `outdoor_spend`),
а `Results` для месяца 2 не содержит вообще ни одной строки, хотя месяц
помечен закрытым. Это не новый баг — это признак того, что фактически
выполняется код **до** прошлого исправления.

**Причина почти наверняка в особенности Apps Script**: сохранение кода в
редакторе (Ctrl+S) НЕ обновляет уже опубликованный `/exec`-URL сам по
себе. Чтобы изменения реально попали в работающее приложение, нужно:

1. Открыть проект Apps Script → вставить актуальный `Code.gs` → сохранить.
2. **Deploy → Manage deployments** → у существующего Web app-деплоя нажать
   значок карандаша (Edit) → в поле **Version** выбрать **New version** →
   **Deploy**. Это ключевой шаг — без него `/exec`-ссылка продолжает
   отдавать старую версию кода бесконечно, даже если в редакторе давно
   лежит новый файл.
3. Ссылка `/exec` при этом **не меняется** — трогать `App.js`/`tablo.js`
   не нужно.

Проверить, что подтянулась актуальная версия, можно так: откройте
`.../exec` в браузере напрямую (без `?action=`) — должно быть
`{"ok":true,"status":"API работает..."}`. Это не подтверждает версию
кода напрямую, но если это НЕ показывается — деплой точно не обновился.
Более надёжно — после деплоя запустите `setupSheets()` и проверьте (см.
ниже), что она пересоздала листы: если у вас после этого `Decisions`
внезапно не 13, а ровно 12 колонок в новом порядке — значит, обновление
подтянулось.

## Что нового в этой версии

**`setupSheets()` теперь удаляет и пересоздаёт игровые листы с нуля** —
как вы и просили. При каждом запуске:

- `Players`, `Rounds`, `Decisions`, `Results`, `BankLog` — **полностью
  удаляются и создаются заново** с гарантированно правильным порядком
  колонок, точно совпадающим с текущим кодом. Любая текущая партия при
  этом стирается.
- `Config` — **не трогается**, только дописываются недостающие ключи
  (как и раньше). Ваш `ADMIN_USERNAME` и все настройки экономики
  сохраняются даже при повторном запуске `setupSheets()`.

Это разграничение специально: `setupSheets()` — операция уровня
"развернуть/переустановить схему", её запускают в редакторе кода;
«Опасная зона → Начать игру заново» в панели администратора — операция
уровня "новая партия между тестами", доступна прямо в приложении, тоже
чистит игровые данные, но не пересоздаёт структуру листов (это не
обязательно после этого исправления, но обе кнопки решают разные задачи).

## Про график на табло за 2 месяца

Это не баг рендеринга — в `Results` для месяца 2 действительно нет ни
одной строки (расчёт либо упал, либо шёл через старую логику, см. выше).
График не может провести линию из одной точки. После того как
подтвердится актуальный деплой и вы пересчитаете хотя бы 2 месяца заново
— линии появятся сами, никаких изменений на самом табло не потребовалось.

## Архитектура (без изменений)

- **`Code.gs`** — бэкенд на Apps Script, JSON API.
- **`index.html` + `Style.css` + `App.js`** — кабинет игрока/администратора.
- **`tablo.html` + `tablo.css` + `tablo.js`** — табло для проектора/ТВ.
- **`EXEC_URL` меняется в ДВУХ местах**: `App.js` и `tablo.js`.

## Порядок действий сейчас

1. Откройте проект Apps Script. Полностью замените содержимое `Code.gs`
   на версию из этого сообщения (не дополняйте — замените целиком).
2. Сохраните (Ctrl+S).
3. **Deploy → Manage deployments → ✏️ (Edit) → Version: New version →
   Deploy.** Это тот самый шаг, которого, похоже, не хватало.
4. Запустите `setupSheets()` — пересоздаст игровые листы с нуля,
   `Config` не тронет.
5. Проверьте лист `Decisions` — должно быть 12 колонок (не 13), в порядке:
   `round_number, telegram_username, price, seo_spend, promo_spend,
   maps_spend, social_spend, outdoor_spend, affiliate_spend, shifts_delta,
   quality_invest, submitted_at`.
6. Откройте месяц 1 заново и проверьте, что после расчёта касса и
   маркетинговые траты выглядят разумно.

## 1. Google Sheets + Apps Script (бэкенд)

1. Создайте таблицу → Расширения → Apps Script (или откройте существующий
   проект — но см. предупреждение выше про New version).
2. Скопируйте содержимое `Code.gs` в редактор, полностью заменив старое.
3. Запустите `setupSheets()`.
4. В листе **Config**: `ADMIN_USERNAME` — ваш ник без `@`;
   `TOTAL_ROUNDS` — длина партии (1–36, по умолчанию 12);
   `ROUND_DURATION_MIN` — минут на приём решений (по умолчанию 5).
5. В листе **Players**: на игрока — только `telegram_username` (без `@`).
6. **Deploy → New deployment → Web app.** Execute as: **Me**.
   Who has access: **Anyone**. Скопируйте `.../exec`-ссылку.
   (Если деплой уже существует — см. «Deploy → Manage deployments» выше
   вместо создания нового, чтобы не менять ссылку в App.js/tablo.js.)

## 2. GitHub Pages (фронтенд)

1. Публичный репозиторий, в корень: `index.html` (строго строчными!),
   `Style.css`, `App.js`, `tablo.html`, `tablo.css`, `tablo.js`.
2. `EXEC_URL` в начале `App.js` и `tablo.js` — ссылка из шага 1.6, в **оба**
   файла.
3. Settings → Pages → Source: `main` / `/ (root)`.
4. Кабинет: `https://<логин>.github.io/<репо>/` — в BotFather.
   Табло: `.../tablo.html` — на проектор/ТВ отдельной вкладкой.

## Технические детали API

`Code.gs` принимает:

- **GET** `?action=identify|dashboard|monitor|config|public|timeline&u=ник`
- **POST** тело `{ "action": "...", "username": "...", "payload": {...} }`,
  `Content-Type: text/plain`. Действия: `submitDecision`, `requestLoan`,
  `repayLoan`, `markBankRead`, `setProfile`, `adminUpdateConfig`,
  `adminOpenRound`, `adminCalculateRound`, `adminResetGame`.

## Что сознательно упрощено в этой сборке (v0)

- Один сегмент рынка вместо трёх (эконом/масс/премиум).
- Переполнение ёмкости — клиенты просто теряются, без перетока к соседям.
- Банкротство — только флаг `status=bankrupt`, без сценариев продажи
  бизнеса/найма — решается вручную с ведущим по ходу игры.
- Формат заведения, реклама (кроме Google Карт) и вложения в качество
  действуют в том же месяце, без лага.
- `VERIFY_TELEGRAM_AUTH` выключен в `Config` — ник берётся из
  `initDataUnsafe` без криптопроверки HMAC.
- Численные коэффициенты 6 маркетинговых каналов — v0-интерпретация
  качественных описаний из брифа, требуют калибровки по живым прогонам.

Все цифры экономики — в листе **Config**, меняются без переразвёртывания
Apps Script (кроме структуры листов) и без прикосновения к GitHub Pages.
