# Развёртывание — v0.2

## Что нового в этой версии

- **Онлайн-табло** (`tablo.html` + `tablo.css` + `tablo.js`) — отдельная страница
  для проектора/ТВ. 4 переключаемых графика по всем месяцам игры: прибыль,
  капитал, доля рынка, обслуженные клиенты. Обновляется сама каждые 10 сек.
- **6 маркетинговых каналов** вместо одного общего бюджета: SEO, промоутеры,
  Google Карты, соцсети, наружная реклама, партнёрская программа — у каждого
  своя механика (см. таблицу ниже).
- **Банк с досрочным погашением**: в кабинете всегда видны задолженность,
  ставка, плановый платёж — независимо от того, брал ли игрок кредит.
- **Полная детализация П&У**: классическая структура Выручка → Себестоимость
  → Валовая прибыль → Аренда/ФОТ/смены/качество/маркетинг → EBIT → Проценты
  → Прибыль → Тело кредита → Cash Flow. Каждая строка — то, что реально
  участвовало в расчёте месяца.
- **`setupSheets()` теперь безопасна к повторному запуску** — добавляет
  недостающие колонки/ключи, не трогает то, что уже есть. Просто запустите
  её снова после обновления `Code.gs`.

## Архитектура (без изменений)

- **`Code.gs`** — бэкенд на Apps Script, JSON API.
- **`index.html` + `Style.css` + `App.js`** — кабинет игрока/администратора,
  статика на GitHub Pages, обращается к `Code.gs` через `fetch()`.
- **`tablo.html` + `tablo.css` + `tablo.js`** — тот же приём, отдельная
  страница в том же репозитории. Ссылка: `.../ваш-репо/tablo.html`.
- **`EXEC_URL` меняется в ДВУХ местах**: `App.js` и `tablo.js`.

## Обновление уже развёрнутого проекта

1. Замените содержимое `Code.gs` на новую версию, запустите `setupSheets()`
   ещё раз — она добавит новые колонки (маркетинговые каналы, детализация
   П&У) и новые ключи в `Config`, ничего не удаляя.
2. Замените `index.html`, `Style.css`, `App.js` в репозитории GitHub Pages.
3. Добавьте `tablo.html`, `tablo.css`, `tablo.js` в тот же репозиторий.
4. `EXEC_URL` в `App.js` и в `tablo.js` — та же ссылка, что уже была.

## 1. Google Sheets + Apps Script (бэкенд)

1. Создайте новую таблицу → Расширения → Apps Script (или откройте уже
   существующий проект, если обновляете).
2. Скопируйте содержимое `Code.gs` в редактор.
3. Запустите `setupSheets()`. Безопасно запускать повторно.
4. В листе **Config**: `ADMIN_USERNAME` — ваш ник без `@`.
5. В листе **Players**: на игрока — только `telegram_username` (без `@`).
6. **Deploy → New deployment → Web app.** Execute as: **Me**.
   Who has access: **Anyone**. Скопируйте `.../exec`-ссылку.

## 2. GitHub Pages (фронтенд)

1. Публичный репозиторий на GitHub, в корень:
   `index.html` (строго строчными!), `Style.css`, `App.js`,
   `tablo.html`, `tablo.css`, `tablo.js`.
2. В `App.js` и в `tablo.js` — константа `EXEC_URL` в самом начале файла.
   Вставьте туда ссылку из шага 1.6 в **оба** файла.
3. Settings → Pages → Source: `main` / `/ (root)`.
4. Кабинет: `https://<логин>.github.io/<репо>/` — в BotFather.
   Табло: `https://<логин>.github.io/<репо>/tablo.html` — выводите на
   проектор/ТВ отдельной вкладкой, в BotFather не нужно.

## Маркетинговые каналы — как это работает

| Канал | Механика | Что это значит для игрока |
|---|---|---|
| SEO | Нужно платить ≥3 месяца подряд, потом эффект включается и держится сам, медленно угасая | Долгосрочная инвестиция, пропуск месяца в начале сбрасывает счётчик |
| Промоутеры | Эффект есть только в месяц оплаты | Быстро, но требует постоянного финансирования |
| Google Карты | Эффект появляется только со СЛЕДУЮЩЕГО месяца после вложения | «Период развития», как и описано в брифе |
| Соцсети | Накопительный эффект в этом же месяце, но забывается быстрее остальных | Классическая реклама, нужна регулярность |
| Наружная реклама | Разовое размещение от 40 000 ฿ держит эффект ровно 4 месяца, потом резкий обрыв | Не плавное затухание — обрыв |
| Партнёрская программа | Не влияет на приток клиентов, увеличивает выручку с уже привлечённых клиентов, пока платите взнос | Отдельный рычаг, не конкурирует с остальными за внимание покупателя |

Все константы (пороги, коэффициенты, длительности) — в `Config`, с
расшифровкой на русском, без переразвёртывания.

## Проверка перед игрой

- `.../?u=<ник_админа>` — пульт ведущего.
- `.../?u=<ник_игрока>` — экран «Добро пожаловать!» → онбординг →
  кабинет с формой решения (форма скрыта, пока месяц не открыт).
- `.../tablo.html` — табло; до первого рассчитанного месяца покажет
  «Пока нет данных».
- Откройте ввод → отправьте тестовое решение → рассчитайте месяц →
  проверьте, что в «Итогах прошлого месяца» Прибыль и Cash Flow видно
  построчно (включая тело кредита) и они сходятся с логикой П&У.

## Технические детали API

`Code.gs` принимает:

- **GET** `?action=identify|dashboard|monitor|config|public|timeline&u=ник`
- **POST** тело `{ "action": "...", "username": "...", "payload": {...} }`,
  `Content-Type: text/plain`. Действия: `submitDecision`, `requestLoan`,
  `repayLoan`, `markBankRead`, `setProfile`, `adminUpdateConfig`,
  `adminOpenRound`, `adminCalculateRound`.

`?action=timeline` — публичный, без авторизации, используется табло:
полная история по всем месяцам и игрокам.

## Что сознательно упрощено в этой сборке (v0)

- Один сегмент рынка вместо трёх (эконом/масс/премиум).
- Переполнение ёмкости — клиенты просто теряются, без перетока к соседям.
- Банкротство — только флаг `status=bankrupt`, без сценариев продажи
  бизнеса/найма — решается вручную с ведущим по ходу игры.
- Формат заведения, реклама (кроме Google Карт) и вложения в качество
  действуют в том же месяце, без лага.
- `VERIFY_TELEGRAM_AUTH` выключен в `Config` — ник берётся из
  `initDataUnsafe` без криптопроверки HMAC.
- Численные коэффициенты всех 6 маркетинговых каналов — v0-интерпретация
  качественных описаний из брифа, а не результат статистического анализа.
  Ожидаемо потребуют калибровки по итогам первых живых прогонов — так же,
  как и вся остальная экономика игры.

Все цифры экономики — в листе **Config**, меняются без переразвёртывания
Apps Script (кроме структуры листов) и без прикосновения к GitHub Pages.
