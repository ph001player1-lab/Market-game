# Развёртывание — коротко

## Архитектура

- **`Code.gs`** — бэкенд на Google Apps Script. Живёт в Google Sheets,
  отдаёт чистый JSON (без HTML), доступен как Web App по `/exec`-ссылке.
- **`Index.html` + `Style.css` + `App.js`** — фронтенд, обычный статический
  сайт. Хостится на **GitHub Pages**, обращается к `Code.gs` через `fetch()`.
- **BotFather** всегда указывает на короткую GitHub Pages ссылку
  (`https://<логин>.github.io/<репо>/`) — она не меняется никогда.
  Меняется только `EXEC_URL` внутри `App.js`, когда вы пересоздаёте
  деплой Apps Script.

## 1. Google Sheets + Apps Script (бэкенд)

1. Создайте новую таблицу → Расширения → Apps Script.
2. Скопируйте содержимое `Code.gs` в редактор (один файл).
3. Запустите функцию `setupSheets()` один раз (▶ в редакторе). Разрешите
   доступ при запросе. Она создаст все вкладки с шапками и заполнит
   `Config` дефолтными цифрами под пхукетский масштаб — с расшифровкой
   каждого параметра на русском в третьей колонке.
4. В листе **Config**: впишите свой Telegram-ник без `@` в `ADMIN_USERNAME`.
5. В листе **Players**: на каждого игрока — только `telegram_username`
   (без `@`). Остальные поля заполнятся сами при первом обращении к игроку
   (лениво, но с записью в лист — числа в Sheets всегда настоящие, не
   пустые). Имя и название заведения игрок вводит сам при первом входе.
6. **Deploy → New deployment → Web app.** Execute as: **Me**.
   Who has access: **Anyone**. Скопируйте `.../exec`-ссылку — она нужна
   только в одном месте, см. следующий раздел.

## 2. GitHub Pages (фронтенд)

1. Новый **публичный** репозиторий на GitHub.
2. В корень — три файла: `Index.html`, `Style.css`, `App.js`.
3. Откройте `App.js`, в самом начале — константа:
   ```js
   var EXEC_URL = 'https://script.google.com/macros/s/.../exec';
   ```
   Вставьте туда ссылку из шага 1.6. **Это единственное место во всём
   проекте, куда вставляется `/exec`-ссылка.** При пересоздании деплоя
   Apps Script меняете только эту строку и коммитите заново — ни
   BotFather, ни сам Apps Script трогать не нужно.
4. Settings → Pages → Source: `main` / `/ (root)`. Через минуту получите
   `https://<логин>.github.io/<репо>/`.
5. **Вот эту** ссылку — в BotFather (`/setmenubutton` или Bot Settings →
   Menu Button), она короткая и не меняется.

## Проверка перед игрой

- Откройте `.../?u=<ник_админа>` (GitHub Pages ссылка + `?u=`) в браузере —
  должен открыться пульт ведущего.
- Откройте `.../?u=<ник_игрока>` (ник, вписанный в Players) — должен
  появиться экран «Добро пожаловать!». Заполните имя и заведение —
  откроется кабинет с формой решения (форма скрыта, пока ведущий не
  нажмёт «Открыть ввод решений»).
- В мониторе администратора у ещё не заполнившего профиль игрока в
  колонке «Подкл.» будет «…», а в «Заведение» — «@ник — ещё не
  открыл(а) кабинет».
- Нажмите «Открыть ввод решений» → у игрока появится форма → отправьте
  тестовое решение → «Рассчитать месяц» → у игрока должны появиться
  итоги с полосой «обслужено / потеряно».

## Технические детали API (на случай отладки)

`Code.gs` принимает:

- **GET** `?action=identify&u=ник` — определить роль (admin/player/ошибка)
- **GET** `?action=dashboard&u=ник` — кабинет игрока
- **GET** `?action=monitor&u=ник` — монитор администратора
- **GET** `?action=config&u=ник` — конфиг для администратора
- **GET** `?action=public` — публичный лидерборд (без авторизации)
- **POST** тело `{ "action": "...", "username": "...", "payload": {...} }`,
  `Content-Type: text/plain` (важно — иначе браузер шлёт CORS-preflight,
  на который Apps Script не отвечает, и запрос падает). Действия:
  `submitDecision`, `requestLoan`, `markBankRead`, `setProfile`,
  `adminUpdateConfig`, `adminOpenRound`, `adminCalculateRound`.

Открытие `.../exec` напрямую в браузере без `?action=` покажет
`{"ok":true,"status":"API работает..."}` — это нормально, значит бэкенд
жив; сама игра открывается через GitHub Pages ссылку.

## Что сознательно упрощено в этой сборке (v0)

- Один сегмент рынка вместо трёх (эконом/масс/премиум) — вернём, когда
  подтвердится, что базовый цикл ощущается правильно.
- Прибыль = денежный поток, за вычетом только тела кредита — без
  амортизации CAPEX.
- Переполнение ёмкости — клиенты просто теряются, без перетока к
  соседям со свободными местами.
- Банкротство — только флаг `status=bankrupt`, без сценариев продажи
  бизнеса/найма — решается вручную с ведущим по ходу игры.
- Формат заведения и реклама действуют в том же месяце, без лага.
- `VERIFY_TELEGRAM_AUTH` выключен в `Config` — ник берётся из
  `initDataUnsafe` без криптопроверки HMAC. Функция
  `verifyTelegramInitData_` уже в `Code.gs`, включить — дело следующей
  итерации, если игра выйдет за пределы доверенной комнаты.

Все цифры экономики — в листе **Config**, меняются без переразвёртывания
Apps Script (кроме структуры листов) и без прикосновения к GitHub Pages.
