# Развёртывание — v0.11

## Что нового в этой версии

### Кнопки — минимум 10 секунд блокировки

Раньше кнопка разблокировалась сразу по ответу сервера — при быстром
ответе (1–2 сек) это выглядело так, будто нажатие не засчиталось, пока
не обновится экран. Теперь блокировка держится минимум 10 секунд
независимо от скорости ответа — этого хватает на смену экрана.

### Табло — вместо таблицы маркетинга теперь 8 новых графиков

Было 5 вкладок (4 графика + таблица маркетинга). Стало 11 графиков +
техданные, все названия сокращены (без «по месяцам»):

`Прибыль · Капитал · Доля рынка · Клиенты · Цена · Бренд · Репутация ·
Качество · Ёмкость · Реклама · Вложения в кач-во · Техданные`

Таблица маркетинга по месяцам убрана целиком — вместо неё «Цена» (график
по игрокам), а «Реклама» и «Вложения в кач-во» показывают расходы по
месяцам как обычные графики. Чтобы это стало возможным, `Results`
теперь хранит `quality` и `capacity` за каждый месяц отдельно (раньше
хранились только `brand`/`reputation`) — без этого построить графики
качества и ёмкости по истории было бы не из чего.

### Техданные — добавлены все параметры маркетинговых каналов

Раздел «Техданные» теперь показывает не только общие цифры (аренда, ФОТ,
себестоимость и т.д.), но и полный набор констант по каждому из 6
каналов из `Config`: вес влияния, «альфа» (масштаб эффекта), опорный
бюджет, а также специфичные для канала параметры — срок разгона и
затухание для SEO, затухание для Google Карт и соцсетей, минимальный
взнос и срок действия для наружной рекламы, минимальный взнос и процент
надбавки для партнёрской программы.

## Обновление уже развёрнутого проекта

1. Замените `Code.gs` — новые колонки `quality`/`capacity` в `Results`,
   расширенный `techInfo` в ответе табло.
2. **Deploy → Manage deployments → ✏️ → Version: New version → Deploy.**
3. Замените `App.js` (10-секундная блокировка кнопок).
4. Замените `tablo.html`, `tablo.css`, `tablo.js` (новый набор вкладок).
5. `index.html`, `Style.css` — без изменений в этой версии.

Историчные месяцы, посчитанные ДО этого обновления, не будут иметь
данных для графиков «Качество»/«Ёмкость» (эти поля раньше не
сохранялись) — начиная с первого месяца после обновления графики
заполнятся.

## Архитектура (без изменений)

- **`Code.gs`** — бэкенд на Apps Script, JSON API, всё через GET.
- **`index.html` + `Style.css` + `App.js`** — кабинет игрока/администратора.
- **`tablo.html` + `tablo.css` + `tablo.js`** — табло для проектора/ТВ.
- **`EXEC_URL` меняется в ДВУХ местах**: `App.js` и `tablo.js` — они
  независимые файлы, ссылку нужно вписывать в каждый по отдельности.

## 1. Google Sheets + Apps Script (бэкенд)

1. Создайте таблицу → Расширения → Apps Script (или откройте существующий
   проект).
2. Скопируйте содержимое `Code.gs` в редактор, полностью заменив старое.
3. Запустите `setupSheets()`.
4. В листе **Config**: `ADMIN_USERNAME` — ваш ник без `@`; `TOTAL_ROUNDS`
   (1–36); `ROUND_DURATION_MIN`; при желании — `START_CAPITAL`,
   `EMPLOYMENT_SALARY`, `REOPEN_THRESHOLD`.
5. В листе **Players**: на игрока — только `telegram_username` (без `@`).
6. **Deploy → New deployment → Web app.** Execute as: **Me**.
   Who has access: **Anyone**. Или «Manage deployments → New version»,
   если деплой уже есть — так ссылка не меняется.

## 2. GitHub Pages (фронтенд)

1. Публичный репозиторий, в корень: `index.html` (строго строчными!),
   `Style.css`, `App.js`, `tablo.html`, `tablo.css`, `tablo.js`.
2. `EXEC_URL` в начале **и `App.js`, и `tablo.js`** — одна и та же ссылка,
   вписанная в оба файла по отдельности.
3. Settings → Pages → Source: `main` / `/ (root)`.
4. Кабинет: `https://<логин>.github.io/<репо>/` — в BotFather.
   Табло: `.../tablo.html` — на проектор/ТВ отдельной вкладкой.

## Проверка перед игрой

- Нажмите любую кнопку с сетевым действием — должна оставаться
  заблокированной не меньше 10 секунд, даже если ответ пришёл быстрее.
- На табло — 12 вкладок в 1–2 ряда (с переносом), включая «Цена»,
  «Бренд», «Репутация», «Качество», «Ёмкость», «Реклама», «Вложения в
  кач-во». После расчёта месяца на каждой из них должна появиться точка
  по каждому игроку.
- «Техданные» — внизу новый блок «Маркетинговые каналы» с параметрами
  всех 6 каналов из Config.

## Технические детали API

`Code.gs` принимает **всё через GET**:

`?action=identify|dashboard|monitor|config|public|timeline|submitDecision|
requestLoan|repayLoan|transferMoney|chooseBankruptcyPath|reopenBusiness|
markBankRead|setProfile|adminUpdateConfig|adminOpenRound|
adminCalculateRound|adminResetGame&u=ник&...остальные_параметры`

`getPublicTimeline` (используется табло) отдаёт по каждому месяцу и
игроку: `profit, cash, marketSharePct, served, price, brand, reputation,
quality, capacity, marketingTotal, qualityInvest` — ровно то, что нужно
для всех 11 графиков.

## Что сознательно упрощено в этой сборке (v0)

- Один сегмент рынка вместо трёх (эконом/масс/премиум).
- Переполнение ёмкости — клиенты просто теряются, без перетока к соседям.
- Формат заведения, реклама (кроме Google Карт) и вложения в качество
  действуют в том же месяце, без лага.
- `VERIFY_TELEGRAM_AUTH` выключен в `Config` — ник берётся из
  `initDataUnsafe` без криптопроверки HMAC.
- Действия идут через GET-параметры, а не тело POST-запроса — для этой
  доверенной комнаты это не меняет модель угроз, но GET-параметры видны
  в логах сервера и истории браузера заметнее, чем тело POST-запроса.
- Техданные теперь показывают игрокам полный набор коэффициентов
  маркетинговых каналов — это ваш осознанный выбор в пользу прозрачности
  над сложностью угадывания; имейте в виду, что это упрощает точный
  расчёт оптимальной стратегии для внимательных игроков.
- Численные коэффициенты 6 маркетинговых каналов, зарплата в найме и
  порог переоткрытия — v0-интерпретация, требуют калибровки по живым
  прогонам.

Все цифры экономики — в листе **Config**, меняются без переразвёртывания
Apps Script (кроме структуры листов) и без прикосновения к GitHub Pages.
