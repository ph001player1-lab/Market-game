# Развёртывание — v0.10

## Табло: скорее всего просто не вписан EXEC_URL

Проверил свой же файл `tablo.js` — там `EXEC_URL` всё ещё стоит как
плейсхолдер `ВСТАВЬТЕ_СЮДА_ССЫЛКУ_НА_ВАШ_ДЕПЛОЙ/exec` (я не знаю вашу
реальную ссылку, вы вписываете её сами по вашей же просьбе). `fetch()` на
такую строку — это невалидный URL без протокола и домена, что даёт
именно `Failed to fetch`. Похоже, ссылку вписали в `App.js`, но забыли
продублировать в `tablo.js` — они независимые файлы, ссылка нужна в
**обоих**.

Теперь при пустом/плейсхолдерном `EXEC_URL` оба файла сразу показывают
понятное сообщение **«EXEC_URL не задан»** вместо криптичного `Failed to
fetch` — так это будет видно сразу, без догадок.

## Кабинет игрока/админа: ошибка теперь диагностируема

Это сложнее — `identify` был обычным `GET`-запросом ещё до прошлого
исправления (POST→GET), поэтому та правка не могла быть причиной именно
этой ошибки. Раз она всё равно возвращает HTML, а не JSON, значит дело
не в методе запроса, а в чём-то на уровне самого выполнения деплоя —
устаревшая версия, требование авторизации, исчерпанная квота Apps Script
или что-то ещё, что я не могу проверить со своей стороны.

**Вместо дальнейших догадок — сделал ошибку самодиагностируемой.**
`apiGet`/`apiPost` теперь не пытаются молча распарсить ответ как JSON, а
при неудаче показывают **код ответа и первые ~300 символов реального
содержимого**. В следующий раз, если ошибка повторится, само сообщение
на экране покажет, что именно прислал Google — страницу входа, ошибку
квоты или что-то третье, и это будет видно сразу, без похода в DevTools.

**Пришлите мне текст этой новой, более подробной ошибки** — по нему
можно будет поставить точный диагноз вместо перебора гипотез.

## Обновление уже развёрнутого проекта

1. Замените `App.js` и `tablo.js` (изменилась обработка ответа сервера).
2. **В `tablo.js` обязательно проверьте и впишите актуальный `EXEC_URL`**
   — в присланном файле это плейсхолдер.
3. `Code.gs`, `index.html`, `Style.css`, `tablo.html`, `tablo.css` — без
   изменений в этой версии.

## Архитектура (без изменений)

- **`Code.gs`** — бэкенд на Apps Script, JSON API.
- **`index.html` + `Style.css` + `App.js`** — кабинет игрока/администратора.
- **`tablo.html` + `tablo.css` + `tablo.js`** — табло для проектора/ТВ.
- **`EXEC_URL` меняется в ДВУХ местах**: `App.js` и `tablo.js`. Оба —
  независимые файлы, ссылку нужно вписывать в каждый по отдельности.

## 1. Google Sheets + Apps Script (бэкенд)

1. Создайте таблицу → Расширения → Apps Script (или откройте существующий
   проект).
2. Скопируйте содержимое `Code.gs` в редактор, полностью заменив старое.
3. Запустите `setupSheets()`.
4. В листе **Config**: `ADMIN_USERNAME` — ваш ник без `@`; `TOTAL_ROUNDS`
   (1–36); `ROUND_DURATION_MIN`; при желании — `START_CAPITAL`,
   `EMPLOYMENT_SALARY`, `REOPEN_THRESHOLD`.
5. В листе **Players**: на игрока — только `telegram_username` (без `@`).
6. **Deploy → New deployment → Web app.** Execute as: **Me**.
   Who has access: **Anyone**. Скопируйте `.../exec`-ссылку — или, если
   деплой уже есть, используйте «Manage deployments → New version», чтобы
   ссылка не менялась.

## 2. GitHub Pages (фронтенд)

1. Публичный репозиторий, в корень: `index.html` (строго строчными!),
   `Style.css`, `App.js`, `tablo.html`, `tablo.css`, `tablo.js`.
2. `EXEC_URL` в начале **и `App.js`, и `tablo.js`** — одна и та же ссылка
   из шага 1.6, вписанная в оба файла по отдельности.
3. Settings → Pages → Source: `main` / `/ (root)`.
4. Кабинет: `https://<логин>.github.io/<репо>/` — в BotFather.
   Табло: `.../tablo.html` — на проектор/ТВ отдельной вкладкой.

## Проверка перед игрой

- Откройте `.../tablo.html` — если `EXEC_URL` не вписан, теперь сразу
  видно сообщение «EXEC_URL не задан», а не глухое «Failed to fetch».
- Откройте кабинет игрока/админа — если ошибка повторится, скопируйте
  полный текст (там теперь код ответа + начало реального содержимого)
  и пришлите его.
- Остальные проверки — как в прошлых версиях (таймер, банкротство/найм,
  переводы, индикация загрузки на кнопках).

## Технические детали API

`Code.gs` принимает **всё через GET**:

`?action=identify|dashboard|monitor|config|public|timeline|submitDecision|
requestLoan|repayLoan|transferMoney|chooseBankruptcyPath|reopenBusiness|
markBankRead|setProfile|adminUpdateConfig|adminOpenRound|
adminCalculateRound|adminResetGame&u=ник&...остальные_параметры`

`getDashboard` возвращает поле `lifecycle`: `active` / `bankrupt` /
`employed` / `left` — фронтенд ветвится по этому полю.

## Что сознательно упрощено в этой сборке (v0)

- Один сегмент рынка вместо трёх (эконом/масс/премиум).
- Переполнение ёмкости — клиенты просто теряются, без перетока к соседям.
- Формат заведения, реклама (кроме Google Карт) и вложения в качество
  действуют в том же месяце, без лага.
- `VERIFY_TELEGRAM_AUTH` выключен в `Config` — ник берётся из
  `initDataUnsafe` без криптопроверки HMAC.
- Действия идут через GET-параметры, а не тело POST-запроса — для этой
  доверенной комнаты это не меняет модель угроз, но GET-параметры видны
  в логах сервера и истории браузера заметнее, чем тело POST-запроса.
- Численные коэффициенты 6 маркетинговых каналов, зарплата в найме и
  порог переоткрытия — v0-интерпретация, требуют калибровки по живым
  прогонам.

Все цифры экономики — в листе **Config**, меняются без переразвёртывания
Apps Script (кроме структуры листов) и без прикосновения к GitHub Pages.
